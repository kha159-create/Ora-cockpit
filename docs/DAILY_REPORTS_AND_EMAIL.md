# التقرير اليومي وتصدير PDF وإرسال التقارير بالإيميل

## 1. التقرير اليومي (الصفحة الرئيسية)

### ما تم مراجعته وإصلاحه

- **المعارض (الفروع):** التقرير اليومي كان يعرض كل المعارض التي تطابق مدير المنطقة فقط، دون احترام فلتر الفرع/المدينة/نوع المعرض. تم **إصلاح** ذلك: الآن يتم تطبيق `allowedStoreIds` على التقرير اليومي، فيظهر فقط الفروع المسموح بها حسب الفلاتر الحالية (فرع واحد، مدينة، معرض/أونلاين).
- **الموظفين:** بيانات الموظفين في التقرير تأتي من نفس مصدر `management_data` و`employees_data`؛ قائمة الموظفين في نافذة «تقرير الموظفين» تُبنى من الموظفين الذين لديهم حركة في الفترة (من أول الشهر إلى أمس) ضمن الفروع المسموح بها فقط.

### مصدر البيانات

- **التقرير اليومي:** `raw` (management_data) — مبيعات أمس، نفس اليوم من العام الماضي، فواتير، زوار، أهداف، يومية متبقية.
- **تقرير الموظفين (PDF):** `empRaw` (employees_data) + `raw` (للأسماء والفروع)، مع تصفية حسب `allowedStoreIds`.

## 2. مقارنة تصدير PDF الموظفين مع الريبو الأصلي

الريبو الأصلي: [orange-dashboard](https://github.com/ALAAWF2/orange-dashboard) — صفحة [أداء الموظفين](https://alaawf2.github.io/orange-dashboard/employees.html) وتصدير PDF من `pdf_export_employees.js`.

### أوجه التطابق

| الجانب | الريبو الأصلي (employees.html) | Ora-cockpit (التطبيق عندنا) |
|--------|--------------------------------|------------------------------|
| الفترة | أمس + الشهر الحالي (MTD) | نفس الفترة (أمس + MTD) |
| التجميع | صفحة لكل فرع، موظفون مرتبون حسب المبيعات | نفس الهيكل (فرع → موظفون) |
| الفرع المعتمد | Primary store = آخر فرع فيه موظف حقق مبيعات في الفترة | نفس المنطق (`empPrimaryStore` من آخر تاريخ مبيعات) |
| من يظهر في التقرير | الموظفون الذين لديهم حركة في الفترة في ذلك الفرع | نفس الفكرة؛ عندنا يمكن أيضاً اختيار «النشطين فقط» (مبيعات > 0) أو تحديد يدوي |
| الأعمدة | أمس (مبيعات، مساهمة، عدد، م. فاتورة)، MTD (مبيعات، هدف، تحقيق، متبقي، يومية) | نفس الأعمدة في `generateEmployeeReportByStore` |
| الصلاحيات | Admin = كل الفروع؛ غير Admin = فروع المدير فقط | نفس المنطق عبر `allowedStoreIds` ومدير المنطقة |

### الفروقات (غير جوهرية)

- الريبو الأصلي يدعم وضع «الشهر السابق» (Previous Month) في التصدير؛ عندنا التقرير من الصفحة الرئيسية = أمس + MTD فقط (يمكن إضافته لاحقاً إن رغبت).
- الريبو الأصلي يضيف صفحة Debug في نهاية الـ PDF؛ عندنا لا توجد صفحة Debug.
- عندنا واجهة اختيار الموظفين (تحديد الكل / النشطين فقط / إلغاء الكل) قبل التصدير؛ في الأصلي يُصدَّر كل من له حركة تلقائياً.

**الخلاصة:** آلية التقرير وطريقة احتساب الموظفين النشطين وربطهم بالفرع مطابقة لآلية الريبو الأصلي؛ الفروقات فقط في واجهة الاختيار ووضع «الشهر السابق» وصفحة الـ Debug.

## 3. إرسال التقارير يومياً الساعة 12 بالإيميل

لجعل التطبيق يرسل التقارير (مثلاً التقرير اليومي + تقرير الموظفين) كل يوم الساعة 12 (بتوقيت السعودية أو غيره)، تحتاج:

1. **مهمة مجدولة (Cron)** تشغّل في الموعد المطلوب.
2. **API في المشروع** تُستدعى من الـ Cron وتقوم بـ:
   - جلب البيانات (مثل `management_data` و `employees_data` من المصدر الحالي).
   - بناء نفس منطق التقرير اليومي وتقرير الموظفين (بدون واجهة).
   - إنشاء ملف PDF (مثلاً بـ jsPDF أو مكتبة أخرى تعمل على السيرفر).
   - إرسال إيميل مع مرفق الـ PDF (عبر SendGrid / Resend / SMTP).

### خيار 1: Vercel Cron (إن كان الاستضافة على Vercel)

في `vercel.json` يمكن إضافة:

```json
{
  "crons": [
    {
      "path": "/api/daily-report-email",
      "schedule": "0 9 * * *"
    }
  ]
}
```

- `0 9 * * *` = الساعة 09:00 UTC يومياً (تناسب تقريباً 12:00 بتوقيت السعودية AST، حسب التوقيت الشتوي/الصيفي).
- للتوقيت الدقيق للسعودية (مثلاً 12:00): السعودية UTC+3 فـ 12:00 AST = 09:00 UTC، أي `0 9 * * *` صحيح لـ 12 ظهراً.

الـ API نفسه (مثلاً `api/daily-report-email.ts`) يجب أن:

- يتحقق من أن الطلب قادم من Vercel Cron (أو من مفتاح سري محفوظ في Environment Variables).
- يجلب البيانات، يبني التقرير اليومي وتقرير الموظفين، يولد PDF ويرسل الإيميل.

### خيار 2: خدمة Cron خارجية (مثل cron-job.org أو GitHub Actions)

- جدولة طلب HTTP يومياً في الساعة المطلوبة إلى:
  `https://your-domain.com/api/daily-report-email`
- إضافة مفتاح سري (مثلاً `Authorization: Bearer YOUR_SECRET`) في الطلب والتحقق منه داخل الـ API لتفادي الاستدعاء من غيركم.

### خيار 3: إرسال الإيميل

يجب إضافة أحد الخيارين في المشروع:

- **SendGrid / Resend / Mailgun:** إنشاء حساب، وضع API Key في Environment Variables، واستدعاء الـ API من `api/daily-report-email.ts` مع مرفق الـ PDF.
- **SMTP:** استخدام Nodemailer (أو غيره) مع بيانات SMTP (Gmail، Outlook، أو سيرفر بريد الشركة) وحفظ البيانات في Environment Variables.

### خطوات تنفيذ مقترحة

1. إنشاء مسار API جديد، مثلاً `api/daily-report-email.ts`، يستقبل طلب GET (أو POST مع تحقق من المفتاح).
2. داخل الـ API:
   - جلب `management_data` و `employees_data` (نفس المصدر الذي يستخدمه التطبيق).
   - تنفيذ نفس حسابات التقرير اليومي وتقرير الموظفين (بدون واجهة)، ثم توليد PDF.
   - استدعاء خدمة الإيميل مع قائمة عناوين ثابتة أو مخزنة في متغير (مثل `REPORT_EMAIL_TO`) وإرفاق الـ PDF.
3. إضافة المتغيرات في Vercel (أو بيئة التشغيل): `REPORT_EMAIL_TO`, `SENDGRID_API_KEY` (أو ما يعادلها)، وأي سكرت للـ Cron.
4. تفعيل الـ Cron في `vercel.json` كما في خيار 1، أو جدولة الطلب من خدمة خارجية كما في خيار 2.

إذا رغبت، يمكن في خطوة لاحقة كتابة هيكل ملف `api/daily-report-email.ts` (بدون مفاتيح حقيقية) مع تعليقات أين تضع جلب البيانات، توليد PDF، وإرسال الإيميل.
